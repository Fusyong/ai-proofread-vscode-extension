# 图书翻译流程开发计划

> **文档定位**：实现/设计说明。与校对共用「切分 → target/context/reference → LLM 处理 → 比较/专项检查」管线；翻译 = 换提示词语义 + **翻译记忆** + **顺序执行**，不另起平行管线。  
> **状态**：规划中（未实现）。契约细则见 §3.5、§1.4、§4；阶段见 §7。

## 1. 目标与原则

### 1.1 目标

在现有工作流下支持**图书（或章节）翻译**，重点保障：

1. **专名/术语一致性**
2. **文风/语域一致性**
3. **语境完整性**（邻段、已译邻段）
4. **可审核**：过程态双语对照 + **段级**一一对应，便于人工审改

### 1.2 原则

| 原则 | 说明 |
|------|------|
| 文档形态 | **以 Markdown 为默认工作载体**；TeX / Typst 偶发，需先转为 Markdown（见 §1.4） |
| **一段一单元** | **一个 Markdown 段落 = 一个翻译单元**（空行分段；块类型细则见 §1.4） |
| 兼容现有管线 | 复用切分、合并、选段/JSON LLM 处理、重叠轮次、diff/勘误表、自定义提示词、源文本特性、替换表 |
| 仿编辑记忆 | **翻译记忆**的维护/注入/挤出仿 `editorial-memory`（global weight + 最近轮次 + archive） |
| 过程 ≠ 交付 | 模型默认输出**过程格式**（`<s>`/`<t>` 双语块 + `<term>`）；交付稿由工具清理得到 |
| 断行整理案外 | PDF 等错误断行由用户**案外**处理；翻译流程不负责纠断行 |
| 顺序执行 | JSON 批译必须**逐项顺序**跑完并更新记忆后再下一项 |
| 精选记忆 | 翻译记忆有权重、可淘汰；前文相似句检索**临时注入、不入档** |
| 标签不与校对管线撞车 | 过程输出**禁止**使用校对用的 `<target>` 表示译文（见 §3.5） |

### 1.3 规范用语

| 用语 | 含义 |
|------|------|
| **翻译记忆（memo）** | 项目级记忆总称，含两类条目：**术语**、**关键译例** |
| **术语** | 专名、领域词等需统一译法的单位 |
| **关键译例** | **句子级别**的双语实例；由**模型自行判定**是否给出。标准：该句译法有一定特殊性、有特定考虑，后续翻译需要参考此译法。非整段自动入库 |
| **翻译单元** | 一个应译的 Markdown 块（通常为段落；见 §1.4）；对应 JSON 一项或一次整段选段 |
| **过程输出** | `<s>`/`<t>` 双语块（可含 `<term>`）+ 可选关键译例块；用于内省、抽取、审核 |
| **交付输出** | 工具剥标签后得到的纯译文 Markdown（及可选无标记双语对照） |
| **相似句检索** | 在已译**原文句**上单语模糊匹配，带出已有译句；**不写入**翻译记忆 |
| **句对侧车** | 为相似检索等保存的源句↔译句索引（可与过程输出派生；≠ 翻译记忆精选库） |

> 与 CAT「Translation Memory」区别：本扩展的翻译记忆是**精选、带 weight/status、可 archive** 的术语 + 关键译例。

### 1.4 文档格式与块类型（已定）

| 格式 | 定位 |
|------|------|
| **Markdown（`.md`）** | 翻译全流程默认与验收基准 |
| **TeX / LaTeX / ConTeXt / Typst** | 偶发；首期转为 Markdown 再译，不承诺原生 |

**块类型 → 是否成为翻译单元（首期）**：

| 块类型 | 首期策略 |
|--------|----------|
| 普通段落（空行分隔） | **翻译单元** |
| ATX 标题（`#`…`######`） | **单独成单元**（通常需译） |
| 列表项 | 按现有 splitter / 空行规则；宜一项一单元 |
| `>` 引用块 | 单独单元 |
| 围栏代码、表格 | **默认跳过**（不送译；交付时原样保留或占位） |
| 纯空白 | 不生成单元 |

过长段落：人工先拆段再切；实现可对超长单元警告。

**行内 Markdown**（`*强调*`、`` `code` ``、链接、注码等）：提示词要求译文侧**尽量保留**同等结构；首期不做 AST 级强制校验。

**译向**：在源文本特性或工作区配置中写明 `sourceLang` / `targetLang`（或等价说明）。  
**温度**：翻译可与校对使用不同默认温度（配置项分离；参考各平台「翻译」场景建议）。

## 2. 现状可复用能力

| 能力 | 用途 | 缺口 |
|------|------|------|
| 切分：`length` / `title` / … / `paragraphContext` | 切块 + 邻段/标题语境 | 缺显式「按段落切分（一项一段）」；无「已译邻段」 |
| 合并 Markdown/JSON → `reference` | 下发样张、seed | 无翻译记忆自动合并 |
| 自定义提示词 + full/item/other | 翻译角色与输出契约 | 无预置「图书翻译」；自定义提示词不自动注入源文本特性 |
| 源文本特性 | 全书体裁/读者/语体/译向 | 缺「由简介/目录/样章生成」提示词 |
| 带记忆选段校对 | 接受写回后维护记忆 | 仅校对语义；批 JSON 不读写记忆 |
| `format paragraphs` 等整理 | PDF 后空行/断行整理 | **案外**；入译前稿面应已规范 |
| 替换表 / 对应关系核对 | 译后统一与变体 | 无术语冲突审计专用命令 |
| 句子对齐（同语） | 校前后勘误 | 翻译审核靠过程段对 |
| `similarity` / Jaccard | 可支撑相似句检索 | 需句对侧车与翻译流程接线 |
| TeX/Typst | 说明有限 | 首期转 MD |

## 3. 目标工作流（产品形态）

```text
整理为 Markdown（TeX/Typst 先转换）
  → 【案外】断行/段落整理；跳过代码块/表等策略按稿面落实
  → 按段落（及标题等，见 §1.4）切分为翻译单元（+ 邻段 context / 可选已译邻段）
  → 资料注入（特性 · 试译样张 · seed · context）
  → 顺序翻译（选段试译 或 JSON 逐段）
       ├─ 注入：翻译记忆 + 相似句（临时）
       ├─ 模型输出：过程态 <s>/<t>（含 <term>）+ 可选关键译例（句级）
       └─ 更新翻译记忆（status 规则见 §3.3）
  → 工具：清理得交付 Markdown；抽术语；派生句对侧车
  → 专项：替换表 + LLM 变体/冲突核对
  → 审核：段级过程对照（标题级用对齐标题）
```

### 3.1 切分（翻译单元）

- **翻译模式默认按 §1.4 块规则切分**：每一 JSON 项 `target` = **恰好一个**翻译单元。
- 可与「标题范围 context」「邻段长度扩展 context」组合：单元仍是一段（或一标题），context 为前后单元。
- 现有「按长度切分」若多段合一，**不适合**直接作翻译批处理。
- **阶段 2**：context 可选「上文原文[+已译] + 下文原文」。

### 3.2 资料注入

| 槽位 | 内容 | 必需性 |
|------|------|--------|
| **prompt / 源文本特性** | 全书特性、译向等；案外「翻译用原文特性生成」提示词 | 可选，**强烈建议** |
| **reference · 文风** | 试译样张（建议 2～3 段）或文风样文；配置如 `styleSamplePath` | **强烈建议**；批译前缺失则**警告可继续**（不硬阻断） |
| **reference · 翻译记忆 seed** | 用户预制术语/少量译例 | 可选 |
| **context** | 前后单元；后续支持已译邻段 | 可选 |

自定义翻译提示词应支持**勾选注入源文本特性**。

### 3.3 顺序执行与翻译记忆更新

入口：

1. **选段试译**（仿 `Proofread Selection with Memory`）  
2. **JSON 顺序翻译**（逐段；一项完成并 patch 后再下一项）  

每项循环：组装注入 → LLM →（选段审改）→ 解析过程输出 → 更新记忆 / 句对侧车。

**status 与批准（已定）**：

| 入口 | 术语 / 关键译例写入 |
|------|---------------------|
| 选段 + 用户接受写回 | 本段抽出条目可直接 `approved`（或先 `candidate` 再一键批准；实现二选一，默认接受即 approved） |
| JSON 批译 | 默认写入 **`candidate`**；章末或每隔 N 段提供「批准本批 candidate」；与 seed 已有条目且译法一致时可 `bump_weight` 而不新增 |

改译法：旧条 `deprecated`，新条 `approved`/`candidate`；禁止静默覆盖。

本段命中已有 approved 术语（无论是否再标 `<term>`）：程序可 `bump_weight`。

### 3.4 专项核对

| 手段 | 职责 |
|------|------|
| 自定义替换表 | 字面完全一致的译名统一；可由术语 `avoid[]→target` 生成辅助表 |
| LLM「译名一致核对」 | 变体、换说、漏标、同名异义 |
| 术语审计报告 | 同 source 多 target 列表 |

### 3.5 过程输出契约（已定）

#### 3.5.1 标签（锁定）

**只使用**下列标签；**禁止**在过程输出中用 `<target>` / `<source>` / `<reference>` / `<context>` 表示双语侧（避免与校对管线混淆）。

```html
<bitext>
<s>原文单元，可含<term>术语A</term>与<term>术语B</term>。</s>
<t>译文单元，可含<term>译名A</term>与<term>译名B</term>。</t>
</bitext>
```

可选：模型认为存在「关键译例」时追加（**句子级**，可多条，亦可为空）：

```html
<key_examples>
<ex>
  <s>具有特殊译法考虑的源句。</s>
  <t>对应译句。</t>
  <note>简要说明特殊性（可选）</note>
</ex>
</key_examples>
```

| 约定 | 说明 |
|------|------|
| 单元粒度 | 一个翻译单元 → **恰好一组** `<bitext>`（一对 `<s>`/`<t>`） |
| 源侧忠实 | 去掉所有 `<term>…</term>` 后，`<s>` 与输入单元**归一化后全等**（归一化规则实现时写死：建议保留段内换行与空格，仅统一 EOL）；程序校验失败则警告，译文仍可落盘 |
| 正文转义 | 正文若需字面 `<` `>`，按约定转义；禁止伪造 `<s>`/`<t>`/`<term>`/`<bitext>`/`<key_examples>`/`<ex>`/`<note>` |
| 角色 | 内省、抽取、段级审核；**不是**交付稿 |

#### 3.5.2 术语标记 `<term>`（已定）

> 不用 `[[…]]`，以免与 Markdown / Obsidian 维基链接冲突。

| 细则 | 说明 |
|------|------|
| 首次标记 | 同一 `<s>` / `<t>` 内，同一术语表面形式**仅标记首次出现**；左右 `<term>` **按出现顺序成对**；其后重复不标 |
| 应标 | 专名、需统一的领域词、称谓/机构等；已在记忆中的术语本段仍标**首次**（便于内省与抽取校验） |
| 不标 | 虚词、普通词、本单元内已标过的重复出现 |
| 最长匹配 | 同位置只标**最长**术语；**禁止** `<term>` 嵌套 |
| 同形异义 | 各义项标该义项首次，或拆成两条术语（`note` 消歧） |
| 可选专项 | 「译名巡检」可全标（非默认） |

#### 3.5.3 关键译例（已定）

| 项 | 说明 |
|----|------|
| 粒度 | **句子**（或等价完整小句），不是整段、不是词 |
| 判定者 | **模型自行确定**是否输出；无则省略 `<key_examples>` 或留空 |
| 标准 | 译法有一定**特殊性**、有**特定考虑**，后续翻译需要参考 |
| 入库 | 经 status 规则进入 `examples[]` / `recentRounds`；禁止把整段 `<bitext>` 默认当作关键译例 |
| 长度 | 建议上限（如源句 ≤120～200 字，实现时配置）；过长应再拆句或放弃升格 |
| `note` | 可选，点明「特殊在何处」 |

#### 3.5.4 清理与文件命名（已定）

**清理工具**产出：

- 纯译文 Markdown（取 `<t>`，剥 `<term>`，按单元顺序空行拼合；跳过块原样拼回）  
- 可选：无标记双语对照  
- 可选：术语候选表；关键译例列表  

过程/结果建议命名（与校对区分）：

- `{basename}.translate.N.json` — 第 N 轮过程/结果  
- `{basename}.translate.N.json.md` — 拼合（过程或译文，由清理模式决定）  
- 交付稿：用户指定或 `{basename}.translated.md`  

**人读 seed** 仍可用 `:::` 行（§4.2）；导入转内部 JSON。过程主格式以本节约定标签为准。

### 3.6 审核与相似句

- 审核靠过程 **段级** `<s>↔<t>`，不依赖事后跨语对齐。  
- 标题/目录级：现有「对齐标题」。  
- **相似句（阶段 2）**：在**句对侧车**的源句上单语模糊 Top-K，注入 `<similar_bitext>`；**不入**翻译记忆。整段相似过粗，不以段为检索单位。

## 4. 翻译记忆：数据模型（仿编辑记忆）

存储：

- Active：`.proofread/translation-memory.json`  
- Archive：`.proofread/translation-memory-archive.json`  
- 句对侧车（阶段 2）：如 `.proofread/translation-bitext-index.json`（或按书稿旁路）

### 4.1 结构草案

```json
{
  "version": 1,
  "terms": [
    {
      "id": "tm_term_…",
      "source": "专名",
      "target": "译名",
      "aliases": [],
      "avoid": [],
      "category": "person|place|org|term|other",
      "status": "candidate|approved|deprecated",
      "weight": 0,
      "exampleSource": "……含该术语的短语境……",
      "exampleTarget": "……",
      "note": "",
      "createdAt": "",
      "updatedAt": ""
    }
  ],
  "examples": [
    {
      "id": "tm_ex_…",
      "source": "源句",
      "target": "译句",
      "status": "candidate|approved|deprecated",
      "weight": 0,
      "note": "特殊性说明",
      "createdAt": "",
      "updatedAt": ""
    }
  ],
  "recentRounds": [
    {
      "id": "round_…",
      "createdAt": "",
      "body": "本轮扁平摘要（可含关键译例要点）"
    }
  ]
}
```

| 层 | 对应编辑记忆 | 用途 |
|----|--------------|------|
| `terms[]` | `global` + weight | 术语；超员低 weight → archive |
| `examples[]` | 可升格的长期句例 | 模型给出的关键译例中值得长期保留者 |
| `recentRounds[]` | `currentRounds` | 最近 d 轮有效摘要/译例要点 |
| `aliases` / `avoid` | — | 异名与忌译；注入时一并给出 |

**status**：仅 `approved` 默认进入注入池（candidate 可在「待批准」视图中查看）。

### 4.2 人读交换格式（seed / 导出）

```text
# 术语行（可选类别、忌译）
专名:::译名:::person
专名:::译名:::person:::忌译1|忌译2

# 术语+短语境（可选；内部无 <term> 亦可）
……专名……:::……译名……

# 关键译例（句级）
源句:::译句
源句:::译句:::特殊性说明
```

### 4.3 Patch 语义

- 术语：`add` / `bump_weight` / `set_weight` / `deprecate` / `approve`；支持更新 `aliases`/`avoid`  
- 关键译例：来自 `<key_examples>`；入 `recentRounds` 与/或 `examples[]`  
- 禁止：语义重复再 add（应 bump）；整段当译例；无特殊性的普通句入库

## 5. 注入策略

对每个翻译单元，按字符预算组装：

1. **源文本特性**（若启用；含译向）  
2. **reference 固定区**：试译样张 + 文风说明  
3. **翻译记忆 · 术语**：本段命中 ∪ weight Top-N（仅 approved；含 aliases/avoid）  
4. **翻译记忆 · 关键译例**：`recentRounds` 最近 d 轮 + 可选高 weight `examples`  
5. **相似句（临时）**：句对侧车模糊 Top-K → `<similar_bitext>`  
6. **context**：邻段原文；阶段 2 可含已译邻段  

注入块标签示例：`<translation_memory_terms>`、`<translation_memory_examples>`、`<similar_bitext>`，以及现有 `<reference>` / `<context>` / `<source-text-hints>`（这些仅用于**请求组装**，不出现在模型过程输出里）。

配置：`termsActiveMax`、`recentRoundsMax`、各块 `injectMaxChars`、`similarTopK`、`similarThreshold`、`styleSamplePath`、`sourceLang`/`targetLang`、翻译用 `temperature` 等。

## 13. 与校对业务的衔接与表述（已定）

> 问题：管线通用（切分 / 合并 / LLM 处理 JSON），提示词已含多种业务，但若工作台与提示词都叫「校对/翻译」易混淆。  
> 原则：**共用管线；用户可见以「工作流（并行/串行）」对齐调度；产品品牌与默认路径继续突出校对。**

### 13.1 提示词字段 `task` 与展示「并行/串行」

内部仍保留（与 `outputType` 正交；**勿**用 outputType 兼作业务分类）：

```text
task: proofread | translate | annotate | restructure | other
```

**用户可见**不展示「任务」细分，只标调度：

| 标注 | 含义 | 对应 `task` |
|------|------|-------------|
| **并行** | 校对管线（JSON 可并发） | proofread / annotate / restructure / other |
| **串行** | 翻译管线（顺序 + 翻译记忆） | translate |

| 约定 | 说明 |
|------|------|
| 预置 | 按语义写死（系统默认/知识核查等 → `proofread` 等并行族；图书翻译 / 译名核对 → `translate`） |
| 自定义 | 创建/编辑时选 **并行** 或 **串行**（并行默认写入 `task: proofread`；细项可在 settings JSON 中改） |
| 侧栏 | **扁平列表**；每条 description 含「并行」或「串行」；**不按 task 分组** |
| 当前项 | 仍按内部 task 分别记忆：`currentPromptByTask.*`（并行族常用 proofread 槽；串行用 translate） |

**入口与校验**（按并行/串行互认）：

| 入口 | 行为 |
|------|------|
| 校对选段 / 校对 JSON / 重叠校对 | 属 **并行** 工作流；当前提示词若为串行 → **警告** |
| 翻译选段 / 顺序译 JSON | 属 **串行** 工作流；非串行提示词 → **硬提示/拒绝** |
| 工作面板「LLM … JSON」 | 随工作流切换校对/翻译动作；校验同上 |

`outputType`（full / item / other）仅约束输出形态，与调度标注独立。

记忆隔离（已有方向）：校对 → `editorial-memory`；翻译 → `translation-memory`；勿混注入。

### 13.2 三层表述约定

| 层 | 用语 | 说明 |
|----|------|------|
| **产品 / 品牌** | **AI Proofreader / AI 校对** | 扩展名、命令分类、活动栏；可加副线「面向编校的文稿 AI」 |
| **工作台** | **并行工作台**（默认）· **串行工作台（实验）** | 按 ExecutionMode 分台；**不再**顶栏并行/串行切换 |
| **对齐语义** | **编辑** / **转换** | `alignmentKind`；决定 codec、diff/过程审核、记忆 adapter |
| **调度** | **并行** / **串行（实验）** | `execution`；批处理默认；与 alignmentKind 正交 |
| **提示词标注** | 编辑\|转换 · 并行\|串行 | 侧栏扁平；不叫「任务」 |
| **动作动词** | 编辑/转换选区；并行/串行处理 JSON | 随当前提示词 AlignmentKind 选 codec |

文档用词：

- 「并行 / 串行」= 批处理调度（ExecutionMode）  
- 「编辑 / 转换」= 对齐语义（AlignmentKind）  
- 「校对 / 翻译」= 品牌与业务细项；**不等于**调度  
- 选段+记忆 = 串行原语；串行批处理 = 自动化循环该原语  
- memoryHistory + 聚类 = 并行与串行共用的一致性工具（实验 · memo）

英文品牌可仍为 Proofreader；对内说明 *proofreading-first*。

### 13.3 工作台与分阶段 UI（最终形态）

```text
并行工作台（默认）
  ├─ 调度固定 parallel；edit|convert 均可
  ├─ 文档整理 / 切分 → 合并 → LLM 处理 JSON（并行）
  ├─ 选区：编辑 / 转换 / 带记忆（memo 实验）
  ├─ 专项：校对向工具 + 记忆聚类（实验）
  └─ 底链：打开串行工作台（实验）

串行工作台（实验 · 独立命令/底链进入）
  ├─ 调度固定 serial；edit|convert 均可
  ├─ LLM 处理 JSON（串行）= 自动化选段+记忆
  └─ 专项：转换记忆 + 同一套聚类
```

| 阶段 | 内容 |
|------|------|
| **A 防选错** | `alignmentKind` + `execution`（及兼容 `task`）；侧栏标注；选区命令 hard 校验对齐类 |
| **B 双台** | 废止顶栏切换；并行默认台 + 串行实验台 |
| **C 记忆历史** | history jsonl + 聚类；active EM/TM 仍分库；memoryKit 整库抽取后续 |

### 13.4 明确不做

| 项 | 原因 |
|----|------|
| 弱化或取消「校对」品牌 | 主业与用户心智 |
| 仅为翻译另做一套切分/合并 UI | 重复建设；工作流切换即可 |
| 侧栏再按校对/加注/重组分组并称「任务」 | 与工作流撞名；用途看提示词名称即可 |
| 用扩展改名解决混用 | 不解决调度与入口校验问题 |

## 14. 架构约束与「和校对差在哪」（已定）

### 14.1 理解校对（口径）

> **对**：翻译与校对共用同一套管线（切分、合并、组请求、调 LLM、续跑、落盘、工作台）；差异应集中在 Task Profile，而不是再做一套扩展。  
> **需补正**：本质差异不止「顺序执行」和「记忆格式」两项，还应加上 **过程输出编解码（OutputCodec）**——模型回什么、怎么解析/清理。其余多为配置与文案。

| 层级 | 与校对是否本质不同 | 说明 |
|------|-------------------|------|
| 切分 / 合并 / 工作台 / 模型路由 | **否** | 按段切分、样张进 reference 等 = 同一能力上的策略/配置 |
| **执行调度** | **是** | 翻译 JSON **必须顺序**（段完成 → 更新翻译记忆 → 下一段）；校对可并行 |
| **记忆** | **是** | 翻译记忆（术语 + 句级关键译例等）≠ 编辑记忆（original/changedTo 等）；宜共用 memoryKit，分 adapter |
| **过程输出 Codec** | **是** | 翻译：`<s>`/`<t>`/`<term>`/`<key_examples>` + 清理得交付稿；校对：全文替换或 item JSON |
| 提示词 / `task` / 按钮文案 | 薄差异 | 数据与壳，不是第二套管线 |
| 注入槽（样张、相似句等） | 薄差异 | Profile 声明槽位清单即可 |
| 批译 candidate 策略 | 薄差异 | 策略挂在 Profile 上 |

顺序执行的主因，正是 **翻译记忆要跨段累积**；若不做记忆，顺序也就不是硬需求——但本方案要做记忆，故调度与记忆绑定。

### 14.2 三层模块边界

| 层 | 职责 | 宜包含 | 不宜包含 |
|----|------|--------|----------|
| **管线层** | 切分、合并、LLM 调用、续跑、落盘、进度 | 现有 splitter/merger/client、JSON 轮次 I/O | 校对/翻译语义、过程标签含义 |
| **任务层 Task Profile** | 某业务如何用管线 | `proofread` / `translate`：task、codec、记忆 adapter、是否顺序、文件后缀、门禁 | 再复制一套切分 UI |
| **能力层** | 可复用零件 | memoryKit、标签解析、相似度、注入预算裁剪 | 绑死某一业务文案 |

翻译 = 注册一个 **translate Profile** 挂上管线，而不是在 `proofreadCommandHandler` 里堆叠大型 `if (translate)`。

### 14.3 宜抽取的复用件

1. **memoryKit**：persist / evict / bump / 注入裁剪；editorial 与 translation 只保留 schema、注入 XML、patch 提示词、路径  
2. **OutputCodec**：`full` | `item` | `translate_bitext`（parse / validate / clean / 抽取）  
3. **注入槽清单**：Profile 声明 `slots[]`，管线按清单拼接  
4. **`assertPromptMatchesEntry(task)`**：入口校验单点复用  
5. **结果命名**：`{base}.{job}.N.json`，`job ∈ proofread | translate`（命令 id 仍可用 `ai-proofread.*`）

### 14.4 可测性

优先单测纯函数（不依赖 VS Code UI）：bitext 解析、源侧全等、term 成对、记忆挤出、注入裁剪、一项一段切分。命令层只做 glue。

### 14.5 有意保持较薄的扩展点

值得做成配置/接口：Task Profile、OutputCodec、Memory adapter、注入槽。  
暂不必插件化：模型路由、整套检索面板、为每个任务重做专项检查树。
