## 一、编辑要完成什么

图书编校要在有限的时间里做完四件事：通读，找出错字、标点和明显病句；在较长的前后文里核对表述、专名、数据和编号是否一致；对照课文、词典、原书核对应查的地方；把确认过的修改落到纸稿或电子稿上，并留下可复查的勘误。

前一件事费目力。一本十来万字的稿要逐字看，时间一紧就容易漏。后三件更费判断。前后说法不一样、同一个人名写法不同、练习题和答案对不上、引文和原文有出入，都不是“再仔细一点”就能稳定发现的，必须在上下文里对照。教参、练习册、注释类图书尤其如此：题目和答案、正文和注释、古诗和权威解释，要在同一处看齐。这些稿在语文社的日常工作里很常见。

三审三校不能减。软件的位置是辅助编辑完成上面四件事，不是代替编辑下判断，也不是代替法定审校程序。

近两年，编辑手里已经不缺“能查字”的软件。真正卡住的是两件事：查出来的结果审不审得过来；这部稿的语境，能不能按编辑自己的需要组织好再交给软件。

## 二、常见审校停在哪里

目前编辑接触到的工具，大致是三层。它们解决的问题不一样，不宜混成一个“传统软件都不好用”。

**第一层是规则型审校**，如黑马、方正里基于词库和规则的检查，以及嵌在 WPS、Word 里的同类插件。文档里高亮出错处，右侧列出错误类型和修改建议，编辑逐条采纳、忽略或替换。黑马的公开介绍就是这个用法：校对完后界面右侧出现侧边栏，逐个点击完成订正。这类工具查错别字、敏感词、领导人排序仍然有用；方正对章节编号、图表序号、参见落空和舆情更熟。短处也明确：长上下文和复杂逻辑弱，古籍、公式误报多。编辑的时间耗在甄别标签上，不是耗在读改完的句子上。

**第二层是已经接入大模型的商业审校**，如更新后的方正、蜜度校对通、武汉数传、中南智校、WPS 的 AI 校对等。病句、专名、一部分知识性差错和前后不一致，它们已经能提。蜜度的出版、期刊版本还能出审校报告和勘误表，期刊形态并用批注和修订痕迹。尽管如此，编辑日常看到的主界面仍是错误列表：右侧按全部、严重、一般、疑似分类，点一条，在正文里定位，再决定替换或忽略。知识库和词库由厂商准备好。编辑不能把“这一课的权威课文、这一题的答案、这一条词典”按自己的切分，放进同一次检查。

**第三层是把稿子贴进通用对话窗口。** 改长句、润色往往可用，但没有书稿流程：十万字怎样稳定切开、题目和答案怎样对齐后成批提交、改动怎样和原稿对齐、个人积累的正误怎样下次再用，都要编辑自己拼接。

2025年7月，《中国出版传媒商报》采访一线编辑，把使用感受说得很具体（中国作家网转载，《编辑使用AI编校工具实感体验》）。有的编辑回忆，早期粗用 AI，感觉是“用了不如不用，还不如自己审快”。有的编辑同时用方正、黑马和蜜度：方正查舆情往往一处即中；黑马标注密，真错埋在一片红色、粉色标记里，要仔细甄别才找得到；蜜度对相隔很远的人名、公司名更敏感。为了质量，一部稿除人工审校外还要分别过三遍软件。编加任务已经很满时，这几乎是奢侈。古籍、学术编辑则提醒另一面：模型会按文意改引文，把“詈”改成“骂”、把“叶”改成“页”；也会把人改错。这些建议必须推翻。越是互联网上检索不到的材料，软件越帮不上忙。

由此可见，2026年的差别已经不在“会不会标出错字”。政治表述、领导人职务和排序、舆情监测，专用工具仍然更合适，本作品不承担、也不替代这一块。商业软件能改病句、能查一部分专名，同样不须否认。差别在于：结果交给编辑时，是一份错误工单，还是一篇可以顺着读下去的修订稿；这部稿的题目、答案和工具书，是厂商菜单里预设的，还是编辑当场组织的。

## 三、本扩展怎样帮编辑做完

AI Proofreader 是作者按本人编校需要开发的 VS Code 扩展。编辑安装扩展，在阿里云百炼、DeepSeek 等平台申请接口密钥即可使用，不必自建服务器。它不是出版社立项建设、验收交付的信息系统。

日常只走一条路。来稿若是 Word，或排版端导出的活字 PDF，先转成 Markdown。Windows 下 PDF 转文本已随扩展附带，不必另装。死文字 PDF（文字已转曲或转成图像）仍须先做识别，这一步扩展不代劳。转出的文本若分段、标题不清，先整理段落，或按目录把标题标出来，否则后面无法按章节切开。

然后按目的切分。查错字和病句，片段宜短，经验上六百到八百字一段较稳，十余万字大约切成三百段。查前后是否一致，则按章节切，或仍用短段，但给每一段配上所在章节的全文当上下文。两种切法可以在同一部稿上先后做。

需要对照时再拼。练习题和参考答案可以拼进同一段，再专门核对指代、题号、数据和单位。古诗的解释不可靠时，把可靠注释放在旁边。专名、文言词可以放上词典条目。这些材料可以是编辑事先准备的文件，也可以先检索本地词典、工作区里的文献和维基百科，由编辑勾选后再并入，不自动写进校对。模型每次看到的是三块文字：要改的这段、可选的上下文、可选的参考资料。参考资料里没有的，提示词要求它不要编。

提示词可以选用现成的，也可以自己写。现成的包括：常规语言文字校对、只报必须改的硬伤、核对前后对应关系、把违和的表述改得顺、依据参考资料做知识核查、按小学语文教材的注音规则处理拼音。同一部稿可以先扫硬伤，再核对题答，需要时再做知识核查。编辑若有一套自己的体例，照这个格式写一条新的提示词，下一本书还能用。选中一段立刻校对，适合边读边改；若要全书体例一致，可以把已经确认的通则记下来，后面的段落自动带上，不必每次重写说明。

模型返回的是改后的文字，不是一串“建议将甲改为乙”。审核在差异对照里完成：原稿中被删的字着深红，终稿中插入的字着深绿，左右或上下并排。编辑沿文脉走，没有改动的地方跳过，改动的地方删除和插入同时看见，当场决定留下、改回或自己重写。确认的修改誊到纸稿上；除非编辑对电子稿有把握，不把模型结果直接当成定稿。需要归档时，再生成勘误表，或导出常用错词，供以后做成自己的检查表。

## 四、和常见审校的差异

本作品不声称查错比黑马、方正或蜜度更准。测试完成后，只报告自己的用时、费用和编辑采纳情况，不拿厂商宣传的准确率作对比。差异在下面三处。每一处都对应编辑少做的一件体力活。

### 1. 审核看全文改动，不看侧栏说明书

常见审校的结果是工单。每一条先读错误类型和解释，再跳回正文看高亮，然后点采纳或忽略。误报和真错排在同一列表里。编辑看到的是“建议替换某词”，不容易一眼判断改完之后整句还通不通。前面引到的“全年开花”，说的就是这种负担：标注越多，甄别越久。早期有编辑觉得 AI“用了不如不用”，往往也不是模型一个字都没改对，而是审建议的时间把省下的通读时间吃回去了。

本扩展把模型的输出当成一版修订稿，用 VS Code 自带的差异编辑器与原稿对齐。眼睛顺着文章走。变红的是删掉的，变绿的是补上的，两处挨在一起，改了哪几个字、句子是否因此改坏，同时可见。未改的段落不必逐条点开。并排或上下，按阅读习惯切换。这和“期刊插件里也能看到修订痕迹”不是同一件事：那里的主操作仍是处理一条条批注；这里的主操作是读改后的文本，只在变色处停下来。若选用只列出需改句子的输出方式，侧栏可以按把握大小筛选，但核对仍回到这篇差异上，避免退回纯标签。

### 2. 流程可以按这一部稿重排

固定下来的是顺序，不是检查项目：

来稿（Word 或活字 PDF）→ 转为 Markdown → 按这部稿的目的切分 → 需要时拼上题目、答案、词典或文献 → 按编辑选定的提示词修改 → 差异对照 → 勘误表。

切多长、按章还是按字数、题目和答案拼不拼、参考资料用哪几条，都在编辑手里。模型不能自己决定“这部稿该查什么”。厂商软件把错误类型做成菜单，换一部稿仍然是那几十类；编辑若要查“练习册的题和答案是否同一题号、同一数据”，只能来回翻，或指望软件恰好做了这一项。

两个日常例子。小学语文练习册：题目与答案拼进同一段，用“对应关系”这一条提示词扫描，编辑再逐条核实，不必在题本和答案之间反复翻页。含文言引文或专名的注释稿：先从本地词典和工作区文献里检出相关条目，编辑勾选后放入参考，再校对目标段落。模型要依据这些材料说话。材料不足时，编辑看到的是把握不足，而不是一条没有出处的断语。查不到的学术材料、版本异文，仍然要编辑自己定，这一步没有省略。

### 3. 长在编辑手里的编辑器上，而不是另一套审校网站

审核和统一体例，用的就是写稿、改稿的那些操作。同一处改法要在全书铺开时，可以多处同时选中、同时修改，不必在侧栏里把同一条建议点几十次。每一轮校对前的稿可以纳入 Git，留下“校之前 / 校之后”，需要时回到上一轮，而不是采纳之后原文消失、只剩一份错误列表。正则替换、个人正误表，用来处理已经确认的体例，避免下一本书从头说明。

这些功能不是为参赛集中加上的。方正稿的带圈序号、题本和答案对不齐、半角标点、重复句，都是处理具体书时遇到的，随后做成命令，下一部同类稿继续用。作者本人做编辑，软件随日常编校改，而不是按通用校对产品的功能清单一次设计完。

因此它适合愿意把流程掌握在自己手里的编辑，不适合只想点一次“开始校对”的场合。点一次就能出报告的商业软件，在舆情、敏感词和交稿前的最后一道筛查上，仍然有本作品替代不了的位置。两者可以先后用，不必互相取消。

## 五、用在哪些书上

以下三例都是编校中的真实类型。工具只负责把疑点摆到编辑眼前，改不改由编辑决定。

**一般书稿。** 初审或复审前，把 Word 或活字 PDF 转成文本，按较短篇幅切开，做一轮语言文字校对。过去第一遍要通读多日，低级错误和知识性硬伤混在一起。现在模型先扫一遍，编辑在差异里处理标红标绿的句子，时间用来查证，而不是用来寻找。政治导向和重大选题仍按原有程序审，不放进这一轮。

**练习册和教参。** 题目与答案、课文与解读要保持对应。过去编辑在两个文件之间翻。现在先把两边标题对齐，再拼到同一段里核对。模型标出题号、数据、指代不一致的地方，编辑打开原题核实。它不能代替编辑判断题目本身对不对。

**文言、注释和需要查工具书的学术段落。** 把词典条目、可靠注释或原书放进参考之后再校。编辑看到的修改旁边有材料，可据此决定采纳或推翻。引文必须保持原文面貌时，凡模型按今人习惯改了古字、异体或专名，一律不听。互联网上没有的版本和考订，不交给它做结论。

在流程中的位置是辅助三审三校。所有结果由合格编辑审核。建议把查证后的修改誊到纸稿上。

## 七、风险与边界

模型会漏、会改过头、会把对的改错。引文、专名、版本尤其如此。所以审核界面必须让删除和插入同时可见，方便编辑拒绝。不能因为跑得快就批量采纳。

片段切得太短，跨段的不一致会漏；片段过长或语境不全，细部又容易糊。同一部稿最好短段和章节语境都走一遍，而不是只宣传一种切法。

知识核查和编辑记忆更费接口费用，按稿件需要选用。活字 PDF 转成文本后，版式不再保留，页眉页码要清，复杂版面要整理段落才能切分。文字已转成曲线或图像的 PDF，须先识别。

本作品不替代三审三校，不替代政治导向、重大选题和舆情的专项审读，也不把模型输出自动写回作为付印定稿。
